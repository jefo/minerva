# Инженерные теги: определения предикатов

Каждый тег — это формальное условие, проверяемое по техническим спецификациям entry.
Предикат = формула, а не мнение. Если компонент удовлетворяет предикату — тег присваивается.
Интерпретация «что эти параметры значат для пользователя» — задача доменных специалистов при аудите.

## Для GPU

### local-llm-viable
**Назначение:** запуск LLM на локальной машине.
**Предикат:** `vram_gb >= 16 AND vram_bandwidth_gbps >= 448`
**Обоснование:** 13B-модель в 4-bit занимает ~8GB VRAM + контекст + системные нужды = 16GB минимум. 448 GB/s — нижняя граница комфортного t/s (7B ~55 tok/s, 13B ~30 tok/s).
**Покрытие:** 5060 Ti 16GB, 5070 Ti, 5080, 5090, 9070, 9070 XT, 9060 XT.

### frametime-gaming
**Назначение:** киберспорт / требовательный гейминг с низким frametime.
**Предикат:** `compute_units >= 28 AND vram_bandwidth_gbps >= 476` (1440p) ИЛИ `compute_units >= 18 AND vram_bandwidth_gbps >= 272` (1080p)
**Обоснование:** bandwidth — главный лимитатор FPS на средних и высоких разрешениях. Для 1440p 144Hz+ нужно ≥476 GB/s.
**Покрытие:** 1440p: 5070+, 9070, 9070 XT. 1080p: все, кроме некоторых бюджетных.

### silent-viable
**Назначение:** бесшумная работа без кастомного охлаждения.
**Предикат:** `tbp_w <= 150`
**Обоснование:** карты ≤150W в damped-корпусе при 25°C ambient не выходят из режима fan-stop в idle и остаются <30 dBA под нагрузкой.
**Покрытие:** 5060 (145W), RTX 4060 (115W).

### sff-compatible
**Назначение:** совместимость с SFF-корпусами (ITX).
**Предикат:** `tbp_w <= 200 AND length_mm <= 260 AND height_slots <= 2.2`
**Обоснование:** стандартный ITX-корпус вмещает карту до 260мм и 2.2 слота. Питание через 1×8-pin (требования к PSU скромнее).
**Примечание:** length и height_slots пока не стандартизированы в frontmatter — заполняются при аудите.

### budget-king
**Назначение:** лучший FPS/₽ в своём ценовом сегменте.
**Предикат:** проверяется не по specs, а сравнением с соседними entry в том же ценовом диапазоне (±30% цены). Присваивается вручную после сравнения.
**Обоснование:** объективное сравнение возможно только относительно других entry в БЗ — это относительный, а не абсолютный предикат.

## Для CPU

### frametime-optimized
**Назначение:** минимизация 99th percentile frametime в играх.
**Предикат:** `l3_cache_mb >= 96`
**Обоснование:** 3D V-Cache — единственный доказанный способ радикально снизить frametime-спайки. До 96MB L3 = 2× CCD × 32MB + 64MB 3D V-Cache.
**Покрытие:** 7800X3D, 9800X3D, 7950X3D.

### productivity-workhorse
**Назначение:** компиляция, рендеринг, AI-тренировка на CPU, многопоточные нагрузки.
**Предикат:** `cores >= 12`
**Обоснование:** ниже 12 ядер — потребительский уровень; 12+ — уверенный workstation.
**Покрытие:** R9 7900, 7950X, Ultra 7/9.

### silent-viable
**Назначение:** бесшумная работа с воздушным охлаждением.
**Предикат:** `tdp_w <= 65`
**Обоснование:** CPU с TDP 65W охлаждается любой башней за $40 в пассивном режиме вентиляторов корпуса. 105W — уже требует активного обдува.
**Покрытие:** 7500F, 7600, 7700, 7900, 9600X, 9700X, Ultra 5 225F, Ultra 7 265F.

### budget-king
Аналогично GPU — сравнение FPS/₽ в своём ценовом сегменте.

## Процесс аудита

1. **Быстрая проверка** — `audit_tags.py` прогоняет все entry через механические предикаты → отчёт
2. **Домен-специалисты** — саб-агенты (GPU-эксперт, CPU-эксперт) получают entry + отчёт → интерпретируют «что значат эти спеки»
3. **ЗавБЗ** — получает интерпретации и вносит изменения: добавляет engineering_notes в entry, исправляет tags, обновляет фронтматтер
4. **Всё в отдельной Git-ветке** → merge после завершения
