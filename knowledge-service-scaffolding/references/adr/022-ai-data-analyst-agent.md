# ADR-022: AI Data Analyst Agent — партнёрский слой над DW

## Контекст

ADR-019 определил capabilities как низкоуровневый интерфейс к Warehouse: `cross-reference`, `comparison`, `lineage-trace`, `pattern-promote`. Это stored procedures — они отвечают на «какие данные есть», но не на «что эти данные значат».

ADR-021 (walkthrough) показал разрыв: между `cross-reference` (возвращает Facts) и открытием GDDR7 Law — работа аналитика-человека. Агент вызвал три `comparison`, заметил паттерн, сформулировал гипотезу, запустил `pattern-promote`. DW-способности дали данные. Интерпретацию дал человек.

Этот разрыв нужно закрыть. Не заменой человека, а появлением AI-партнёра, который делает то же что аналитик — но быстрее, на больших объёмах, и без пропуска неочевидных паттернов.

Пользователь minerva — не «баба с ноготочками, клацающая "создай отчёт"». Пользователь — data-аналитик, который понимает домен, но хочет партнёра, а не инструмент. AI-агент здесь — не автопилот, не замена. Это второй аналитик за столом.

## Решение

### 1. Два слоя capabilities

```
┌─────────────────────────────────────────────┐
│         AI DATA ANALYST AGENT                │
│  Высокоуровневый интерфейс                   │
│  «Что интересного в RTX 5060?»               │
│  «Какие паттерны связывают 5060 и 4060?»     │
│  «Что изменилось с новым драйвером?»         │
│  → переводит интент в цепочки DW-операций    │
│  → интерпретирует результаты                 │
│  → предлагает гипотезы                       │
├─────────────────────────────────────────────┤
│         DW CAPABILITIES (ADR-019)             │
│  Низкоуровневые stored procedures            │
│  cross-reference, comparison, lineage-trace   │
│  dim-read, fact-read, pattern-promote         │
│  → только данные, не интерпретация           │
└─────────────────────────────────────────────┘
```

**DW Capabilities (ADR-019):** «что в Warehouse?» Отвечают данными. Без интерпретации. Детерминированы. Контрактны.

**AI Data Analyst:** «что эти данные значат?» Переводит высокоуровневый интент в цепочки DW-вызовов. Строит гипотезы. Предлагает Laws. Работает в exploratory-режиме (как NotebookLM), но с доступом к structured Warehouse.

### 2. Роль AI-агента: партнёр, не автопилот

| Аспект | Автопилот (не наш путь) | Партнёр (наш путь) |
|---|---|---|
| **Кто принимает решения** | AI публикует Laws и Artifacts сам | AI предлагает. Человек утверждает |
| **Кто задаёт вопросы** | «Создай отчёт по RTX 5060» — и всё | «Что интересного?» → AI показывает → человек: «вот это разверни» |
| **Ответственность** | На AI. «Почему этот Law в обзоре?» — «AI так решил» | На человеке. «Почему этот Law в обзоре?» — «Вот lineage DAG, вот моё решение» |
| **Exploratory vs routine** | AI делает рутину. Человек — только сложное | AI предлагает и рутину, и открытия. Человек решает что важно |
| **Confidence communication** | AI: «FPS = 68 (уверен)» | AI: «FPS = 68. Но есть противоречие с источником B. Проверь» |

**Партнёрство означает:**
- AI **предлагает**, не публикует
- AI **показывает неуверенность**, не притворяется
- AI **спрашивает**, когда данных недостаточно
- Человек **принимает решения**, но не обязан проверять каждую мелочь
- Человек **направляет**: «это интересно, разверни»

### 3. Высокоуровневые интенты → цепочки DW-операций

AI-агент принимает интенты на естественном языке и переводит их в последовательности DW-capabilities. Это основная интеллектуальная работа агента: **intent routing.**

| Интент пользователя | Разложение агентом | DW-операции |
|---|---|---|
| «Что интересного в RTX 5060?» | 1. Найти GPU → 2. Все Facts → 3. Сравнить с предшественником и конкурентом → 4. Найти аномалии | dim-read → cross-reference → comparison (3×) → anomaly-detect |
| «Какие паттерны связывают RTX 5060 и RTX 4060?» | 1. Найти оба → 2. Сравнить все метрики → 3. Выделить где разница > 20% → 4. Проверить есть ли Laws объясняющие разницу | dim-read (2×) → comparison → filter → lineage-trace |
| «Что изменилось с новым драйвером 575?» | 1. Найти старые Observations (572) → 2. Найти новые (575) → 3. Сравнить по каждому game+config → 4. Показать где разница > 5% | cross-reference (2×, разные driver) → comparison (N×) → impact-analysis |
| «Собери обзор RTX 5060» | 1. Все данные GPU → 2. Все Laws → 3. Coverage → 4. Competitive → 5. Narrative View → artifact-compile | dim-read → cross-reference → lineage-trace → artifact-compile |
| «Есть ли противоречия в данных по RTX 5060?» | 1. Все Facts → 2. Сгруппировать по game+config → 3. Проверить противоречия | cross-reference → group → conflict-check |

**Ключевой навык агента — intent routing:** понять что пользователь хочет (исследовать? сравнить? собрать? проверить?) и разложить на цепочку DW-операций. Без этого агент — просто голосовой интерфейс к capabilities.

### 4. Самостоятельный discovery

AI-агент может работать без явного запроса пользователя — в фоновом режиме:

```
Агент (фон): «В Warehouse появились новые Observations для RTX 5060.
             Сравнил с RTX 4060 по 5 играм.
             Обнаружил: GDDR7 даёт +30% bandwidth при той же ширине шины.
             Это похоже на паттерн. Проверить?»

Пользователь: «Да. Сравни ещё с RTX 4070.»
Агент: «Сравнил. Паттерн подтверждается. Предлагаю Law: GDDR7 Bandwidth Compensation.
      Lineage DAG готов. Принять?»
Пользователь: «Принимаю. И добавь в Engineering Mart.»
Агент: pattern-promote → ✅
```

**Discovery pipeline:**

```
Новые Facts в Warehouse
    ↓ (триггер: fact-insert)
Агент проверяет: есть ли паттерн?
    ↓ cross-reference + comparison по связанным Dimensions
Обнаружен candidate pattern
    ↓
Агент формулирует гипотезу и предлагает пользователю
    ↓ (пользователь: «интересно, проверь»)
Агент доисследует: дополнительные comparison, поиск контрпримеров
    ↓
Агент предлагает Law с готовым lineage
    ↓ (пользователь: «принимаю»)
pattern-promote
```

### 5. Обработка неуверенности

AI-агент не притворяется уверенным когда данных недостаточно:

| Ситуация | Реакция агента |
|---|---|
| Один Observation, confidence 0.95 | «RTX 5060: 68 fps в CP2077 1440p. Один замер. Надёжно.» |
| Два Observation, противоречие (68 vs 72) | «Два замера расходятся. Источник A: 68 (user). Источник B: 72 (reviewer). Нужен третий.» |
| Нет данных для сравнения | «RTX 4060 не имеет замеров в CP2077. Не могу сравнить. Импортировать?» |
| Law предложен на 2 Facts | «Закон основан на 2 Observations. Confidence: 0.7. Рекомендую ещё 2 Observation для повышения.» |
| Impact analysis: Law требует проверки | «GDDR7 Law требует перепроверки. Новый драйвер 575. Запустить comparison?» |

### 6. Пользовательский интерфейс (концептуальный)

Это не UI-дизайн, а модель взаимодействия:

```
Пользователь: «Что интересного в RTX 5060?»

Агент:
  «RTX 5060: 8GB GDDR7, 128-bit, 355 GB/s, 150W, $299.

  Три наблюдения в 3 играх. Покрытие: 3/9 целевых игр (33%) — низкое.
  Рекомендую импортировать Alan Wake 2, Black Myth, TLOU2.

  Сравнение с RTX 4060 (предшественник):
    +30.5% bandwidth (GDDR7 vs GDDR6 на той же 128-bit шине)
    +30.7% FPS в CP2077 (68 vs 52)
    −15% цена/производительность

  Обнаружен candidate pattern: GDDR7 компенсирует 128-bit шину.
  2 из 3 необходимых comparison готовы. Нужен comparison с RTX 4070.
  Проверить?»
```

Это не «отчёт». Это диалог. Пользователь решает что важно, куда копать, что публиковать.

### 7. Что фиксируем сейчас

**Архитектурное намерение.** AI Data Analyst Agent — отдельный слой над DW-capabilities. Не реализация. Не конкретный model provider.

**Границы слоя:**
- **Вход:** высокоуровневые интенты на естественном языке
- **Выход:** интерпретации, гипотезы, candidate Laws — требующие утверждения человеком
- **Не выход:** автоматически опубликованные Laws и Artifacts

**Отношение к DW-capabilities:**
- AI-агент вызывает DW-capabilities — это его инструменты
- DW-capabilities не знают о существовании AI-агента — они обслуживают любого потребителя
- Добавление AI-слоя не меняет контракты DW-capabilities

**Партнёрская модель:**
- AI предлагает → человек утверждает
- AI показывает неуверенность → человек принимает risk decision
- AI исследует автономно → человек направляет

## Что НЕ фиксируем

- **Конкретную модель.** GPT, Claude, Gemini — implementation detail
- **Prompt engineering.** Как именно агент переводит интенты в цепочки DW-операций — implementation
- **Discovery-алгоритмы.** Как агент находит паттерны — implementation (но архитектурно это: cross-reference → group → compare → detect anomalies)
- **UI.** Чат? Голос? Интеграция в IDE? — implementation
- **Background agent.** Фоновый режим — future. Сначала — диалоговый

- **ADR-019:** низкоуровневые DW-capabilities — инструменты для AI-агента

## Последствия

**Что становится проще:**
- **Пользователь не учит DW-схему.** «Что интересного?» вместо `cross-reference(dim_ref=..., fact_type=...)`
- **Discovery масштабируется.** Агент проверяет все новые Facts на паттерны, не ждёт пока аналитик заметит
- **Рутина автоматизирована.** «Сравни с предшественником» — 3 вызова. «Сравни со всеми конкурентами» — 15 вызовов. Агент делает, аналитик интерпретирует
- **Неуверенность явная.** Агент говорит когда данных мало, когда есть противоречие, когда Law слаб. Аналитик принимает risk decision осознанно

**Что требует проектирования (будущие ADR):**
- **ADR-0XX: Intent Routing** — как агент переводит высокоуровневые интенты в цепочки DW-операций
- **ADR-0XX: Discovery Engine** — алгоритмы поиска паттернов: anomaly detection, cross-dimension correlation, candidate Law generation
- **ADR-0XX: Agent-Human Partnership Protocol** — модель взаимодействия: когда агент действует автономно, когда спрашивает, когда ждёт
- **ADR-0XX: Agent Confidence Model** — как агент оценивает уверенность в своих выводах и коммуницирует её

**Что требует дисциплины:**
- **Агент — не издатель.** Все writes (pattern-promote, artifact-compile) — только после утверждения человеком. Технически: `pattern-promote` требует флаг `approved_by: "human"`. Без него — rejected
- **Агент — не оракул.** Предлагает гипотезы, не истины. «Candidate Law: GDDR7 Bandwidth Compensation (confidence: 0.7, основан на 2 Facts)» — не «GDDR7 Law»
- **Граница AI/DW — священна.** AI-агент не пишет в Warehouse напрямую. Только через DW-capabilities. Только с контрактами
